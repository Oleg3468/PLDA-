# Веб-сервис PLDA (экспериментальный)

Локальный веб-сервис, который оборачивает правила и модули PLDA в рабочий
инструмент: чат-исследование, поиск по каталогу официальных источников,
генерация черновиков записок и очередь проверки юриста.

> Как и вся база PLDA, сервис не является юридической консультацией и не
> заменяет адвоката. Автоматически он выдаёт только рамки исследования, план и
> источники — выводы по существу остаются за человеком.

## Возможности

| Компонент | Что делает |
|---|---|
| **Чат** (`/`) | Структурированный ответ по правилам `docs/PROMPT_FOR_ANY_AI.md`: рамки, факты, план исследования, источники |
| **Поиск источников** | Локальный каталог официальных источников (RAG без векторов) с честными статусами «проверено ДАТА / требует проверки» |
| **Записка** | Черновик по шаблону `docs/templates/legal-memo.md` со ссылками на источники; скачивается в .md |
| **Проверка юриста** | Очередь документов: редактирование, одобрение («проверено юристом»), отклонение |
| **Обезличивание** | E-mail, телефоны, номера дел/карт и IP маскируются перед любой отправкой текста во внешнюю LLM |

## Запуск

### Самый простой способ — файл запуска

1. Скачайте репозиторий на компьютер (кнопка **Code → Download ZIP** на GitHub и распакуйте, либо `git clone`).
2. **Windows:** дважды щёлкните `start.bat`
   **Linux/macOS:** выполните в терминале `./start.sh`

Файл сам создаст окружение, установит зависимости и запустит сервис;
браузер откроется на `http://localhost:8000`. Остановка — **Ctrl+C**
в окне терминала. Требуется только установленный Python
(Windows: https://www.python.org/downloads/, при установке отметьте
«Add Python to PATH»).

### Запуск вручную (те же шаги по отдельности)

```bash
# Windows: py -m venv .venv  и далее .venv\Scripts\...
git clone -b arena/01a0f6fb-plda https://github.com/Oleg3468/PLDA-.git
cd PLDA-
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/uvicorn app.api.main:app --host 0.0.0.0 --port 8000
```

### Включение полноценного режима ИИ (необязательно)

Перед запуском задайте ключ OpenAI-совместимого API:

```bash
# Linux / macOS
export PLDA_LLM_API_KEY="ваш-ключ"

# Windows (cmd)
set PLDA_LLM_API_KEY=ваш-ключ
```

При первом старте база `database/plda.db` создаётся автоматически и
наполняется стартовым каталогом украинских источников
(`database/seed/ukraine_core.json`). Пересчитать сид вручную:

```bash
.venv/bin/python -m database.seed_ukraine
```

## Переменные окружения

| Переменная | Назначение | По умолчанию |
|---|---|---|
| `PLDA_DB_PATH` | Путь к SQLite-базе | `database/plda.db` |
| `PLDA_LLM_API_KEY` | Ключ OpenAI-совместимого API; включает LLM-режим | не задан (оффлайн) |
| `PLDA_LLM_BASE_URL` | Базовый URL API | `https://api.openai.com/v1` |
| `PLDA_LLM_MODEL` | Модель | `gpt-4o-mini` |
| `PLDA_ROOT` | Переопределение корня проекта (наследие ядра) | корень репозитория |

Ключи хранятся только в окружении и никогда не попадают в Git и базу.

## Режимы работы

- **Оффлайн (по умолчанию).** Внешние вызовы не выполняются. Ответ строится
  детерминированно из модулей ядра (`app/core/`) и локального каталога
  источников: рамки исследования, план, источники. Выводов по существу
  права не формирует — по правилам PLDA их нельзя дать без проверки
  первоисточников.
- **LLM.** Если задан `PLDA_LLM_API_KEY`, тот же запрос уходит в
  OpenAI-совместимую модель с системным промптом из
  `docs/PROMPT_FOR_ANY_AI.md` и блоком локальных источников со статусами
  проверки. При ошибке LLM сервис автоматически откатывается в оффлайн-режим
  и честно сообщает причину.

## API

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/api/health` | Статус, режим, счётчики источников |
| GET | `/api/eval` | Прогон «золотого набора» контрольных вопросов (отчёт о качестве) |
| POST | `/api/chat` | `{message, jurisdiction, anonymize, session_id, history}` → ответ + источники |
| POST | `/api/analyze` | Анализ запроса: цель, категория, план, факты |
| GET | `/api/sources` | `?q=&jurisdiction=` поиск по каталогу источников |
| POST | `/api/memo` | Генерация записки → документ в очереди проверки |
| GET | `/api/documents` | Список документов (`?status=pending_review\|approved\|rejected`) |
| GET | `/api/documents/{id}` | Полный документ |
| POST | `/api/documents/{id}/review` | `{action: approve\|reject, content_md?, reviewer_note?}` |

Поддерживаемые юрисдикции ядра: UA, DE, FR, PL (каталог источников сейчас
наполнен для UA; для остальных используйте `docs/legal-library/` вручную).

## Приватность

- База SQLite хранится локально; `database/*.db` исключены из Git.
- Перед отправкой в LLM текст маскируется (`app/services/anonymizer.py`):
  e-mail, телефоны, номера дел, номера карт, IP. Полное обезличивание имён
  не гарантируется — не отправляйте чувствительные данные, если политика
  LLM-платформы не проверена.
- История чата пишется только в локальную базу.

## Честность источников

Каждый источник в каталоге несёт статус: `verified` + `checked_at` (дата
фактической проверки ссылки) либо «требует проверки». Стартовый набор
(21 запись) наполнен 2026-10-01: 10 позиций проверены в этой сессии через
официальный портал/поиск, остальные помечены как непроверенные — номера и
адреса даны по официальной картотеке. Пример важности проверки: в ходе
наполнения выяснилось, что Господарський кодекс (№ 436-IV) по официальной
картотеке утратил силу — он сохранён в каталоге с явной пометкой.

## Что НЕ реализовано (осознанно)

- Автоматическая актуализация законодательства и live-загрузка текстов
  законов (сроки и редакции нужно проверять по ссылкам).
- Выводы по существу и юридические заключения без человека.
- Полнотекстовая векторная база права (тексты законов не хранятся, только
  описания-указатели).
- Аутентификация, мультипользовательский доступ, аудит-логи — сервис
  рассчитан на локальное использование.
- Проверка юриста — это процесс: интерфейс очереди есть, но саму проверку
  выполняет человек со статусом/компетенцией.

## Тесты и оценка качества

```bash
.venv/bin/python -m pytest tests/
```

Покрытие: анонимизатор, поиск источников, сид базы, все эндпоинты API
включая сценарий «записка → очередь → правка → одобрение юристом»
(55 проверок).

**Золотой набор** (`tests/golden/legal_questions.json` + `app/services/evaluator.py`):
12 контрольных правовых вопросов для обеих плоскостей анализа с ~100
автоматическими проверками — RAG находит ожидаемые официальные источники,
плоскости «физлицо»/«человек» отражаются в ответе, обязательные элементы и
дисклеймеры на месте. Запуск: `pytest tests/test_golden.py` или
`GET /api/eval`. Метод перенят у RRSI (google-research/rrsi): любые
изменения промптов, правил, сида или карточек агентов должны проходить
набор полностью; падение кейса — регрессия, которую нужно объяснить
до слияния изменений.
